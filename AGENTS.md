# Pane

A Mac app that mirrors an Android emulator in a clean window, inside a device frame we draw, and forwards clicks, scrolls, keys and frame-button presses to it over the emulator's own gRPC interface (`EmulatorController`). It also starts emulators headless. Android emulator only. Status: v1 and the tools (More menu, Open link, Inspect layout, Measure, Pick colour, emulator switcher, one window per emulator) built 2026-11-17, waiting for Jatin to try them.

- Plan and decisions: `../plans/pane.md` (Nidus Labs workspace). Research with sources: `~/Work/personal/.claude/research/emulator-mirror-grpc.md`.
- Design canvas: [Pane design](https://claude.ai/artifact/SSy48PyDrNEapFzTWwoybJ). Studio design rules: `../docs/mac-app-design.md`.

## Layout

A Swift package, no Xcode project. Swift 6, strict concurrency, macOS 15+.

- `PaneCore` (no UI, all unit-tested):
  - `Discovery/`: running emulators from `~/Library/Caches/TemporaryItems/avd/running/pid_*.ini` (port, token, AVD) with a folder watcher; AVDs from `~/.android/avd`; the SDK's emulator binary; each AVD's `config.ini` (model, Android version, screen, density).
  - `Launcher/`: starts an AVD headless through the Pane Emulator helper (`LaunchedEmulator`, the PID; `Process` only when the bundle has no helper, as under `swift run`) and stops emulators by PID.
  - `Client/`: `EmulatorConnection` (plaintext HTTP/2 gRPC with the bearer token: `streamScreenshot` in RGBA with both sides set, one long-lived `streamInputEvent`, status, rotate, PNG screenshot), `StreamFrame` (each streamed `Image` read straight from the wire into a pooled IOSurface `CVPixelBuffer`, BGRA, at most six out per stream, shown by the layer with no further copy) and the reconnect backoff.
  - `Geometry/`: the frame layout for any size and the four orientations, window points to device pixels, the Window menu sizes.
  - `Input/`: key mapping (W3C names, typed text) and scrolling as a touch drag (phone AVDs have no wheel device, so `WheelEvent`s are dropped).
  - `Capture/`: file names like macOS's own, the save folder (`CaptureLocation`: macOS's screenshot `location`, else the Desktop), where a capture goes (`CaptureOutcome`: under Save to's "Same as macOS screenshots" the toolbar's Screenshot button follows macOS's `target-screenshot`, else `target`: clipboard copies, preview opens a temporary PNG in Preview, anything else saves a file; ⌘S always saves, ⇧⌘C always copies, recordings always save; Desktop or a chosen folder always saves), `CaptureNotice` (the pill's words after a capture: "Saved to <folder>.", "Copied.", none for Preview, "Recording saved to <folder>.", the failures) and `CaptureGate` (one screenshot in flight at a time), `FrameRecorder` (H.264 `.mov` from the frames, variable frame rate; the frame on screen at Start is written at time 0 and the last frame again at Stop, so a still screen, which gets no frames from the emulator, still makes a movie as long as the recording; `RecordingTimeline` places each frame), `GifExporter` (a recording as a GIF, ImageIO) and `FramedScreenshot` (Pane's frame drawn around a screenshot on a clear background).
  - `Transfer/`: `DropPlan` (what a dropped file is: `.apk` installs, the rest copy to `/sdcard/Download`, media is scanned), `ApkBadging` (`aapt2 dump badging` from the real SDK's newest build-tools), `InstalledPackage` and `VersionChange` (`dumpsys package`, compared by versionCode), `DragCard` (the drag card's header, title and chip copy), `DropJob` (apps first in drop order, then files; per-file states; the several-file title) and `DropDismissal` (the 6 s close), `DropTransfer` (push to `/data/local/tmp`, then `pm install -r -t [-d]`), `DropFailure` (plain sentences, adb's line behind Details) and `DeviceIntent` (Open: the launcher activity; Show: `VIEW_DOWNLOADS`), and `Adb` (the real SDK's adb through `Process`, serial `emulator-<console port>`). `Adb.run(_:timeout:)` runs any argument array and returns the output, `Adb.runProcess` any local tool with a timeout; `adb shell` joins its arguments for the device's shell, so quote typed text with `deviceShellQuoted`.
  - `Tools/`: `DeviceLink` (Open link: validation, the `am start` arguments, adb's failure in one line) and `RecentLinks`; `DeviceAppearance`, `DeviceTextSize`, `DeviceLocation`; `LayoutTree` (the `uiautomator dump` parser, hit-testing, parent frames), `DensityScale` (px × 160 / density), `EdgeDistances`, `ScreenScale`; `MeasuredLine` and `SnapEdges`; `PickedColour` and `PixelGrid`.
  - `Windows/`: `WindowRoster` (one window per emulator, where an attach request goes) and `SwitcherEntry` (the switcher's rows: device kind, running, starting or stopped, the second line with the model truncating before " · Android N", "In another window", "Starting", what VoiceOver reads).
  - `Clipboard/`: `ClipboardSync`, the rules for text moving between the Mac's clipboard and the device's (gRPC `setClipboard`, `getClipboard`, `streamClipboard`).
  - `Takeover/`: "Show All Emulators in Pane" state and runner, and `AttachRequest` (`pane://attach?avd=` and `--attach <avd>`).
  - `Generated/`: protoc output, committed.
- `Pane`: the app.
  - `Theme/ThemeTokens.swift`: the studio's design tokens, generated in the assets repo (`assets/tokens.json`) and copied by `scripts/sync-tokens.sh` (`--check` says when the copy is stale; `build-app.sh` warns). Never edit it; change a shared value in `assets/tokens.json`, rebuild there, then sync. `Theme/ThemeColour+Look.swift`: token colours are drawn with `.nsColor` / `.swiftUI` (through `ColourLook`, so Increase Contrast holds in SwiftUI), never the generated `.color`; `.opaque` is the solid form where no blur is drawn.
  - `Theme.swift` holds every size and colour under Pane's names (menus in `Theme.Menu`, the tool pill in `Theme.ModePill`, tool drawing in `Theme.Tools`, tool colours `Palette.tool…`). Shared values read `ThemeTokens`; the numbers still written there are Pane's own, with no token yet (listed as tokens to add in `../design/adoption/pane.md`).
  - `main.swift`: `AppDelegate` (the windows, one `PaneWindowController` each, the roster, attach requests, the `pane://check-…` URLs), `PaneWindow` and the More toolbar item.
  - `PaneWindowController`: one window and its `PaneModel`; the window delegate; runs `DeviceCommand`s; opens the menu panels and sheets; remembers each emulator's window position.
  - `PaneModel` owns the connection, the emulator Pane started, sizes, recording and the input rules; `PaneModel+Device.swift` has screenshots, GIF export, Open link and the device's appearance, text size and location.
  - `PaneSettings`: everything remembered between launches, in one observable type (the Settings window binds to it).
  - `MenuPanel.swift`: Pane's own menus (`PaneMenu` holds the rows and the keys, `PaneMenuPanel` draws them; rows can carry a device glyph with its status dot (`DeviceGlyph`, `StatusDot`), the selected fill, a second line in two parts and a row button (`MenuRowButton`), and a panel can open on a row). More, the emulator switcher and the emulators menu use it; never `NSMenu`, which also can't be shown or captured while Pane is in the background. `DeviceMenu.swift` builds their rows and the menu bar's native items from the same `DeviceCommand`s.
  - `Drop/`: `DropModel` (the drag card's reads, the drop's queue, the downgrade question, Open and Show, Return and Esc, the close timer, VoiceOver announcements) and `DropViews.swift` (`DropLayer` inside the screen: the dim and moss outline, the drag card, the result card).
  - `Tools/`: `ToolsModel` (Inspect layout, Measure, Pick colour: one at a time, the screen's pointer is theirs while one is on) and `ToolOverlays.swift` (what they draw, the mode pill, the notice line).
  - `Sheets.swift`: the sheet scaffold, Open link, Set location, `ConfirmSheet` (Restart and Shut Down for an emulator Pane didn't start, with Cancel the default) and the Export GIF sheet.
  - `Kit/`: the Nidus component kit, the same as Drop's (last synced both ways 2026-11-17, Drop `e38e4be`: Increase Contrast plumbing, hairlines, `displayOptions()`, controls' own accessibility frames): `Kit` (`Kit.swift`: the kit's names over `ThemeTokens`, plus Drop's own values not yet tokens), `Controls.swift` (button, switch and field styles, Tab-focusable even with macOS Keyboard navigation off, `FocusVisibility`), `Select.swift` (`NidusSelect`, its own menu in a child panel), `KitComponents.swift` (the panel card, window backdrops, `RowCard`, `SettingsRow`, `SwitchRow`, `PopupPanel`, `FrameSlide`, `WindowPresence`), `Motion.swift` (`blurFade`, `StatusSwap`, and Drop's `RollingNumber`, copied 2026-11-17 with `Theme.Motion` renamed `Kit.Motion` and the `roll*` values in `Kit.Motion`; during a roll the new text stays one `Text` with its changed characters left out, so unchanged ones keep their shape in context, such as SF's raised colon between digits, changed 2026-11-18 in both apps). Settings and the update surfaces draw with `Kit`; the emulator window keeps `Theme`. Shared values come from `ThemeTokens.swift`; change one in `assets/tokens.json`, never here. A kit code change still goes into both apps in the same session, never one alone; Drop's kit doesn't read the tokens yet (`../design/adoption/drop.md`).
  - `Settings/`: `SettingsView.swift` (board 14: the page, `SettingsWindowController`, Save to's choices) and `TakeoverSwitch` (Show all emulators in Pane: changing and failed states around the script).
  - `Updates/`: besides the engine (below), `UpdateViews.swift` (the popup, the Settings banner, `UpdatePopupController`, which is the `UpdateSurface`) and `UpdateCopy.swift` (every string the surfaces show, tested).
  - `Chrome.swift` is the title bar (`SwitcherTrigger`, board 20: the device name and model line are the switcher's pop-up button) and the toolbar under the device (board 19: `RecordButton` is one view whose width and time move on `Spring.toggle` while its two icons, separate images each in its own colour, crossfade over `fade` (a symbol replace on one image recoloured it at once, so Stop showed the red icon in ink for about 100 ms), the time a `RollingNumber` on `RecordingClock`, paused while the window is hidden; `MotionOptions` reads Reduce Motion and Dim Flashing Lights); `CaptureFlash` (in `Tools/ToolOverlays.swift`, beside `NoticePill`) is board 18's flash; `StateViews.swift` holds the no-emulator, progress and can't-connect screens; `PaneContentView` lays out the frame; `MainMenu` is the menu bar.
- `PaneEmulatorHelper` (product `PaneEmulator`): "Pane Emulator", a background-only app (`LSBackgroundOnly`, `NSAppSleepDisabled`, ID = Pane's + `.emulator`) that `build-app.sh` bundles at `Contents/Helpers/Pane Emulator.app` and signs before Pane, with the same identity and the hardened runtime. Its `main.swift` sends output to the log, writes its PID to a file and `exec`s the emulator.
- `Resources/AppIcon.icns`: the app icon, from the assets repo (`../assets/apps/pane/`); refresh with `scripts/sync-icon.sh`, never edit it by hand. `build-app.sh` bundles it, and the update surfaces draw it from the bundle (`PaneIcon`).
- `Protos/`: the vendored proto and the emulator version it came from.
- `Resources/Assets.xcassets`: Pane's custom symbols (`pane.home`, `pane.rotate.left`, and the switcher's `pane.device.phone`, `pane.device.tablet`, `pane.device.foldable` from board 20's glyphs), generated by `scripts/make-symbols.py` from measurements of Device Hub's toolbar (never Apple's artwork) and compiled by `build-app.sh` with `actool`. Edit the script, not the SVGs.
- `scripts/emulator-takeover.sh install|uninstall|status`: the shadow SDK at `~/Library/Android/pane-sdk` (no spaces: the NDK breaks on them) whose `emulator` is a wrapper (adds `-no-window` to AVD launches and opens Pane on that AVD), plus a marked block in `~/.config/fish/config.fish`, `~/.zprofile` and `~/.zshrc` (backed up first). Bundled into the app for the menu item; env overrides (`PANE_REAL_SDK`, `PANE_SHADOW_SDK`, `PANE_FISH_CONFIG`, `PANE_ZSH_CONFIGS`) let checks run it on scratch copies. Pane itself always launches from the real SDK.

## Design

- Chrome measured from Apple's Device Hub with the Accessibility API (title 28 pt past the traffic lights, 36 pt glass capsule and circle under the device). Boards: the [Pane design](https://claude.ai/artifact/SSy48PyDrNEapFzTWwoybJ) canvas (window boards 1 to 6, tools 7 to 13, kit 16).
- **The emulator switcher is built to board 20, option A** (2026-11-18; it replaces board 13's switcher). The trigger shows its chevron and hairline outline at rest; the panel opens on this window's row; "Open in new window" is a row button (Right onto it, Left or Esc back, Command-Return from the row), never a submenu. Contracts: `SwitcherTrigger` and `DeviceStatus` (`../design/contracts/apps/pane/`) and MenuPanel's selected, keyboard and rowButton states. `-PaneSwitcherFake three|starting|other|long|one|none` (debug) fills it with board 20's examples.
- **Tools are built to boards 7 to 11 and 13.** Tool colours are fixed in both modes because they draw on the device: moss `#4F7A4A` for outlines and lines, amber `#B25E00` (always dashed) for distances and snap guides, a paper halo around both, ink chips. Pick colour's loupe reads the frame Pane is showing (scaled down in a window smaller than the device); a click takes a full-resolution screenshot (`EmulatorConnection.screenshotFrame`) and copies the device's own pixel.
- **The window is glass in light mode too** (a deviation, below). Paper tint 93% and ink tint 86% keep secondary text at 4.5:1 over pure black or white (`GlassTests` holds it); Reduce Transparency and Increase Contrast make it solid.
- **Settings and updates are built to boards 14 and 15** with Drop's kit: Settings is white in light and ink glass in dark (solid with Reduce Transparency or Increase Contrast), 560 wide, centred, as tall as its page up to 720. The update popup is the top-right notification panel and never takes focus.
- **Increase Contrast:** every dynamic colour resolves through `ColourLook`, which also reads the system setting, because SwiftUI resolves `Color(nsColor:)` with a plain light or dark appearance. Hairlines go through `Hairline` / `Kit.hairlineWidth` (1 pt under Increase Contrast). Every hosting root ends in `.displayOptions()`, which carries the debug flags into SwiftUI's environment.
- **Disabled is `opacity.disabled` (0.45), applied once.** Borderless buttons use `.plainRow` (`PlainRowButtonStyle`), never `.plain`, which dims a disabled label again on its own.
- **Drag and drop is built to "Option A · Card on the device screen" with the refined drag card, variant 1** (2026-11-17). The card stays inside the device screen, so it can't cover the toolbar, title or frame buttons. A refused drag (no emulator, only folders) puts it at the top with no dim; on a window too short for it and the no-emulator text, the text steps aside while the drag lasts (`DropModel.stateStepsAside`, measured in the screen's coordinate space).
- **The window is never narrower than the switcher plus its margins** (`Theme.Window.minWidth`, 270 pt). A narrow phone's smallest screen grows until the window is that wide (`DeviceFrameLayout.smallestScreenHeight`), so every menu drawn inside the window fits and the device name stays readable; the old floor (360 pt screen, a 227 pt window for a Pixel 8) cut the switcher and More and left one letter of the name (review 2 round 3, S1). A sideways or wide device keeps the 360 pt floor. Panels that still don't fit beside their menu (More's submenus) shift over it, inside the window.
- **Every confirmation is a Nidus sheet** (`ConfirmSheet`, `SheetPresenter`), never `NSAlert`. Destructive ones (Restart emulator, Shut down emulator, for an emulator Pane didn't start) make Cancel the moss primary, rightmost and the default (Return), and the action a secondary capsule (Button's destructive variant; decided by Jatin 2026-11-17). Others make the action the moss primary and the default. Esc always cancels.
- `scripts/build-app.sh` stamps the real SDK version into the binary with `vtool`. SwiftPM records the deployment target there, which makes AppKit draw the pre-macOS 26 look (12 pt traffic lights, no glass toolbar items).

## Design deviations

Everything Pane does that is not on a board or differs from the kit (`../docs/design-language.md`, "Staying inside the language"). Each line: what (the token or contract, Pane's value), why, decided by, date.

- **Light window is glass, not solid paper** (`surfaceBase` light `#FFFFFF`; Pane draws `app.pane.color.glassLight`, paper at 93%, over the `.underWindowBackground` material, and solid paper under Reduce Transparency or Increase Contrast). Why: Jatin's choice of look; the dark device frame sits on a soft ground, as in Device Hub. 93% keeps secondary text at 4.5:1 over pure black (`GlassTests`). The material is `.underWindowBackground`, not Drop's `.popover`, because this is a document window, not a popover. Decided by Jatin, 2026-11-17 (`../plans/pane.md`). Approved.
- **Sheets are 355 wide** (`size.sheet.confirmationWidth` is 420). Why: at the default size the window is 383 wide (315 screen, 2 × 10 bezel, 2 × 24 inset), so a 420 sheet would hang over it. Recorded by the token-adoption build from the approved plan (`../design/adoption/pane.md`, group D), 2026-11-17.
- **Start emulators without sound is on by default** (board 14 draws it off). Why: Pane always passed `-no-audio`, so on keeps today's behaviour. Proposed by the build agent. Approved by Jatin, 2026-11-17.
- **The inspect card has a Label row** when the view has text (board 9 has none). Why: the text is how you find the view again. Proposed by the build agent. Approved by Jatin, 2026-11-17.
- **The inspect card moves out of the way** (board 9 draws it under the outline): under the outline, else above it, else at the screen's bottom or top. Each distance chip stays beside its guide (under a level one, right of an upright one) and slides only along it, overhanging the guide's outer end on a short guide; a chip that fits nowhere on its guide drops "px", then hides, rather than leave its guide (`LabelPlacement.placeOnGuide`). So nothing covers another label or the outline. Why: review 2 found chips and the card on top of each other; review 2 round 2 found chips moved off their guides. Proposed by the review-fix agent. Approved by Jatin, 2026-11-17 (chips back on their guides, 2026-11-17).
- **Location's first choice is "Default", not "None"** (board 7), and the Set location sheet says "until you choose Default." Why: the choice puts the GPS back at the emulator's own default, which None didn't say. Proposed in commit 655b887. Approved by Jatin, 2026-11-17.
- **Version row, builds that can't update** (board 15 has no such state): the caption says "This build doesn't update itself." and Check for Updates stays disabled in place. Why: debug and ad hoc builds carry no feed or key, so a check can't run. Proposed by the build agent. Approved by Jatin, 2026-11-17.
- **Version row, a spinner before "Checking…"** (board 15 shows the words only). Why: a check can take a few seconds and the words alone look stuck. Proposed by the build agent. Approved by Jatin, 2026-11-17.
- **Export Recording as GIF confirms in a Nidus sheet** (no board; `Sheet` / Confirmation): title "Export recording as GIF", "The GIF is saved next to the recording.", a card row with the recording's whole name (up to two lines) over a small "Choose another…", then Cancel and a moss Export. Export is not destructive, so Return runs it; Esc cancels. Why: it replaced a system alert with three equal buttons. Proposed by the review-fix agent. Approved by Jatin, 2026-11-17.
- **Destructive sheet buttons have no trash icon** (Button's destructive variant draws one): Restart emulator and Shut down emulator delete nothing, so a trash would say the wrong thing. Proposed by the kit-sync agent, 2026-11-17. Approved by Jatin, 2026-11-17.
- **Menus, the ⓘ popover and the inspect card blur within the window** (`inkGlass` says a behind-window `.hudWindow` blur): `surfaceMenu` dark (and `tool.chip`) over a within-window `.hudWindow` blur, solid under Reduce Transparency or Increase Contrast. Why: they are drawn inside Pane's window over the device, so a behind-window blur would blur the desktop and leave the device's text sharp under them. Proposed by the review-fix agent. Approved by Jatin, 2026-11-17.

- **Emulator switcher, proposed by the build agent, 2026-11-18. Approved by Jatin, 2026-11-18:**
  - The trigger's focus ring is reached by Esc from the open switcher, not by Tab (board 20 says "Tab reaches the name first"). Why: Tab in the emulator window is the device's own key (`KeyMapping`), and taking it would stop Tab reaching Android. VoiceOver presses the trigger as before.
  - Pressed and open look the same (the 12% shade): the switcher opens on mouse down, as a pop-up button does, so there is no separate pressed moment.
- **Capture feedback (boards 18 and 19), built 2026-11-18. Approved by Jatin, 2026-11-18:**
  - The screenshot flash is white (`Theme.CaptureFlash.colour`), not `brand.paper` (`#F4F4F6`) as board 18 says. Why: it stands for the device's own camera flash, so it stays white in both modes, as `captureFlash.yaml` says.
  - Record's icon crossfades between two images, each in its own colour, over `fade` (board 19 says a symbol replace). Why: a symbol replace on one image recoloured it at once, so Stop showed the red icon in ink for about 100 ms.
- **Drag and drop, proposed by the build agent, 2026-11-17:**
  - The drag chip says "Reinstall" when the device has the same version (the plan's copy list has none for it). Approved by Jatin, 2026-11-17.
  - Several items are titled by the first name and a count ("Splito and 2 more"); the board's "2 apps and 1 file" repeated the chip "2 apps, 1 file". The refined board is regenerated to match. Approved by Jatin, 2026-11-17.
  - After the drop the version chip keeps the drag's words (New, Update from 1.3.2, Older than 1.5.0, Reinstall); option A drew "Replaces 1.2.0" and "Downgrade from 1.3.0". Approved by Jatin, 2026-11-17.
  - A list row with Open or Show shows the tick alone, without "Installed" or "Copied", so the name keeps its room at 315 pt. Approved by Jatin, 2026-11-17.
  - The reading spinner shows beside the chip after 1 s (the plan's rule; no board draws it). Approved by Jatin, 2026-11-17.
  - A drop while another runs is refused; booting, connecting and can't-connect windows refuse a drag with no card (the board's "Start an emulator first" would be wrong there). Approved by Jatin, 2026-11-17.
  - A narrow window drops the drag card's icon before the chip would be cut. Approved by Jatin, 2026-11-17.

Not deviations, for the next review: the Save to select's fill is paper (`#F4F4F6`, `surfaceRaised` in `tokens.kit.json`; settled by Jatin 2026-11-17, board 14 to follow), and its menu (tick on the right, soft open ring, width = max(select, content), no divider) follows the Select contract. The switcher's Open in new window submenu (board 13) is gone: board 20 replaced it with a button on the highlighted row (approved by Jatin 2026-11-18).

## Commands

Homebrew's LLVM env breaks Xcode builds, so build through `scripts/swift.sh`, which clears it:

```sh
scripts/swift.sh build
scripts/swift.sh test
scripts/build-app.sh [--debug]     # build/Pane.app, ad hoc signed
scripts/format.sh                   # swift format; --lint for the strict check
scripts/generate-protos.sh          # regenerate Sources/PaneCore/Generated (pinned protoc in .claude/tools)
```

**Checking the app without taking focus** (`.claude/checks/`, gitignored; `lib.sh` wraps the common steps):
- `relaunch.sh [args]` quits the Pane it started (menu Quit, then SIGTERM) and opens a new one with `open -g`; `-NSRequiresAquaSystemAppearance YES` for light.
- `window-info.swift <pid>` finds the window; capture with `screencapture -l <id> -o -x`.
- Input posted to the PID, window-local points, nothing activates: `click` (with hold or drag), `move.swift` (pointer moves), `scroll.swift`, `key.swift`.
- Accessibility: `axpress.swift <pid> <title> [--menu]` presses a button or menu item (a trailing `*` matches a prefix); `axdump.swift` prints the tree with bounds; `axsize.swift` resizes.
- Capture feedback (boards 18 and 19): `cf-clip.sh <name> <seconds> shot|shot2|rec -- <flags>` records the window with ScreenCaptureKit (`winrec.swift`, by window ID, no focus) during a capture into `.claude/screens/capture-feedback-built/` (an .mp4 and its frames); `lum.swift` and `rowscan.swift` measure the flash and the toolbar's width per frame; `cf-mem.sh` counts the 2 KB and 2.5 KB blocks over a 2-minute recording. The emulator sends frames only when its screen changes, so `rec` opens the app list during the recording. `fixes/` has its own debug copy (`run.sh`, `quit.sh`, by PID), `fixes/clip.sh <name> <s> rec|recstill` and `fixes/darkdot.swift <frames>`, which finds the Record icon in every frame and flags a filled disc in the text colour (ink fill about 0.55 normally, 1.0 on the old Stop bug). The light-mode flag didn't always take on 2026-11-17 (the Mac was in dark mode); check a clip's mode before naming it.
- `movinfo.swift` checks a recording; `pixels.swift` and `contrast.py` sample colours.
- Debug-build flags: `-PaneCaptureFolder <dir>` (screenshots and recordings never go to the Desktop in checks), `-PaneReduceTransparency YES`, `-PaneIncreaseContrast YES`, `-PaneAVDHome <dir>` (fixture AVDs in `.claude/checks/fixture-avd`), `-PaneNoAutoAttach YES` (keeps the no-emulator screen up), `-PaneScreenCaptureLocation <value>` and `-PaneScreenCaptureTarget <value>` (stand in for macOS's screenshot folder and Save to target; never read or change the real ones), `-PaneReduceMotion YES` and `-PaneDimFlashingLights YES` (the capture flash and Record's transition fall back), `-PaneScreenshotDelay <seconds>` (holds a screenshot's frame back, to see the in-flight state), `-PaneRegistrationFolder <dir>` (fake emulators: `.claude/checks/fake-sdk` registers on a dead port, run with `open --env ANDROID_HOME=…`).
- Drops and paste can't be posted to a background window, so the debug build takes `pane://check-hover?file=…`, `check-hover-end`, `check-drop?file=…` and `check-paste` (same handlers), plus `-PaneTreatAsKey YES` and `-PanePasteboard <name>` (a private pasteboard; `pb.swift <name> [text]` reads or writes it), so checks never touch the real clipboard. `uidump.py` prints the device's text nodes.
- `build-debug.sh` builds the debug copy straight into `.claude/checks/debug` (`PANE_APP=<path> scripts/build-app.sh`), so the copy running from `build/` is never replaced under Jatin. `v2.sh` wraps the debug copy's steps (`drun`, `dquit`, `dshot`, `dmenu`, `dpress`, `dclick`, `dmove`, `dkey`, `durl`, `dlog`); `axmenus.swift` prints the menu bar with shortcuts and ticks, `axclose.swift` closes a window, `pbtypes.swift` shows what is on the private pasteboard.
- More debug URLs: `check-open-link?text=…` and `check-location?lat=…&lon=…` (the sheets, prefilled; press their buttons through Accessibility), `check-gif?file=…`, `check-switcher`. `-PaneSwitcherFake <case>` replaces the switcher's emulators with board 20's examples (`three`, `starting`, `other`, `long`, `one`, `none`). Posted pointer moves don't reach a background window's hover tracking, so `check-switcher-hover?title=1|0`, `?row=N` (counting from the panel's header, 0) and `&button=1` set the hover. `.claude/checks/switcher-built/capture.sh light|dark` captures every board 20 state into `.claude/screens/switcher-built/` (`DRY=1` runs it without the emulator). Menu panels take posted keys (`key.swift --code 125` is Down, 124 Right, 36 Return, 53 Esc) and a posted click on the title opens the switcher.
- Settings and updates: `-PaneBackgroundCheck YES` opens every window behind the others without activating Pane (the popup too, at the normal level); `-PaneTakeoverCheck ok|changing|failed` stands in for the takeover script (always pass it in a check: the real switch edits the shell setup); `-PaneSlowStartAfter <seconds>` shortens the slow-start wait. - **How much device checking a change needs** (the full soak is for one rare emulator race, about one crash in nine app-close rounds on 37.2.13; 10 minutes, about 33 rounds, misses a still-buggy build about 2% of the time, 3 minutes about 31%, so a short soak is no test of it):
  1. Every change: unit tests, lint and the build (CI).
  2. A change that touches the device, the stream or recording: a 1 to 2 minute smoke check (attach or Start, frames flowing, one rotation, open and close a couple of apps, record 5 s).
  3. The full 10-minute soak, only when the race could come back: a new emulator build (the beta updates itself), a change to how Pane starts the emulator (arguments, `-no-window`, the helper), or a change to how Pane streams (number of streams, size, when they restart, such as rotation's restart). Memory soaks (`.claude/checks/mem/`) only for frame or recording pipeline changes.
- The debug build logs at debug level under subsystem `dev.niduslabs.pane`; `log show` skips debug lines, so use `log stream --level debug`.

## Conventions

- **Never log or print the gRPC token.** `GRPCToken` redacts every textual form; only the `authorization` header sees it.
- **Every press ends in a release:** mouse up, drag off the screen, pointer exit, window or app losing focus. Held keys and a wheel's scrolling finger too.
- **Pane only stops emulators it started** (by PID); restarting any other asks first in a sheet. Stop on a slow start stops only the process Pane launched.
- **Errors are plain sentences.** adb's own reason goes behind Details (`DropFailure`, `Adb.reason`, `Adb.detail`), never in the sentence.
- **Never log clipboard contents,** only that text moved. **The clipboard moves only while Pane's window is key:** text copied elsewhere on the Mac reaches the device only when pasted (Command-V) into Pane.
- **Pane never starts an emulator on its own:** only Start and Restart do (both logged). One stopped from outside (`adb emu kill`) shows Start.
- **Dependencies pinned with `exact:`** and `Package.resolved` committed. gRPC Swift 2 needs macOS 15.
- **Generated code is committed and never edited.** To update: copy the new proto into `Protos/`, note its emulator version there, run `scripts/generate-protos.sh`.
- **Theme constants only;** views hold no raw numbers, and `Theme`/`Kit` hold no shared value by hand (`../design/checks/static`, `--app pane --root .`). Format and lint with Apple's `swift format` (`.swift-format`, lint `--strict` clean); generated code is excluded.
- **Unsandboxed:** the App Sandbox blocks the registration folder.
- **While a tool is on, nothing reaches the device:** clicks, scrolls, keys and frame buttons are the tool's. Esc or Done ends it.
- **One window per emulator.** Asking for an emulator a window already shows brings that window forward. Closing the last window quits Pane and leaves emulators running.
- **The title bar takes clicks before SwiftUI content under it,** so `PaneWindow.sendEvent` hands a click on the device name to the switcher, and the model tracks the pointer over it for the hover shade.
- **Menu bar shortcuts** (the panels show the same): Open Link ⌘L, Save Screenshot ⌘S, Copy Screenshot ⇧⌘C, Inspect Layout ⌥⌘I, Measure ⌥⌘M, Pick Colour ⌥⌘P, New Window ⌘N.
- **One agent drives the emulator at a time** (shared device, see the workspace guide).
- **Memory while streaming:** frames go into pooled IOSurfaces (`StreamFrame`), never a `Data` and `CGImage` per frame, and the bundle launches with `MallocLargeCache=0` (`LSEnvironment`, written by `build-app.sh`). Without it macOS keeps the gRPC transport's freed per-frame buffers dirty: 300 MB to 1.1 GB of footprint with almost nothing live. A copy started without LaunchServices (the bare binary) doesn't get it. Measurements and the checks: `~/Work/personal/.claude/research/pane-memory.md`, `.claude/checks/mem/memsoak.sh`.

## The emulator build

Write-up with the evidence: `~/Work/personal/.claude/research/pane-emulator-crashes.md`.

- **Emulator 37.2.13 (stable) crashes while anything streams its screen and an app closes.** Each `streamScreenshot` frame is read back on the emulator's PostWorker thread through a GL context that exiting app render threads also use, with no lock (gfxstream); Metal then aborts ("A command encoder is already encoding to this command buffer"). One stream is enough, scaled or full size; Android Studio's embedded view takes the same path. Pane can't avoid it from its side.
- **This Mac runs the beta emulator, 37.3.9 (build 16863232),** installed into the real SDK on 2026-11-17 (Jatin's decision) with `sdkmanager --sdk_root=$HOME/Library/Android/sdk --channel=1 emulator`. It ran the same soaks clean (10 minutes each with the bare client, one Pane window and two Pane copies; 37.2.13 died in 5 of 5 such runs). Don't go back to 37.2.13, and soak a newer build (`soak/`) before trusting it.
- **Rolling back:** download Google's stable archive (`https://dl.google.com/android/repository/emulator-darwin_aarch64-16740729.zip`, SHA-1 `6c5e61b873e11c7d1d08683bea089f762baee070`), stop the emulator, move the SDK's `emulator` folder **out of the SDK** and unpack the archive's `emulator` folder in its place, then run `scripts/emulator-takeover.sh status`. Never leave a renamed emulator folder inside the SDK: `sdkmanager` takes it for the installed package and upgrades it in place (that is how the first backup was lost).
- **Pane keeps asking for frames at the window's size.** Full-size frames take the same path in the emulator, double the latency and data, and drop frames in Pane (measured in a debug build: 14 ms and 1 dropped frame at Fit Screen, 33 ms and 720 dropped frames in 79 busy seconds at Pixel Accurate, which asks for full size).
- **An emulator Pane starts writes its output to `~/Library/Logs/Pane/emulator-<avd>.log`** (the launch before it is `.previous.log`). A graphics crash prints its reason there and nowhere else.
- **Quitting or killing a Pane copy never stops an emulator,** also not the copy that started it (`soak/vanish.sh`).
- **Pane starts emulators through the "Pane Emulator" helper, so Pane leaves the Dock when it quits.** On macOS 27 an emulator started from Pane's own process (`Process`, `posix_spawn`, even with `setsid`) is in Pane's process coalition and keeps Pane's app record alive after Pane quits: the Dock shows "Running in Background" and Background Task Management records "Pane - background tasks". So `EmulatorLauncher.launch` runs `/usr/bin/open -g -n "Pane Emulator.app" --args <pid-file> <log> <emulator> <arguments…>` (Android variables passed with `--env`). LaunchServices starts the helper in its own coalition with no parent app; the helper writes its PID and `exec`s the emulator, so that PID is the one the emulator registers with, and Pane stops it by PID as before. `NSWorkspace.openApplication` records Pane as the helper's parent and launchd jobs stay tied to the app, so both were rejected. That `open` sets no parent is observed, not documented: recheck on each macOS release (a regression shows as `childASNs:` on Pane's `lsappinfo` record after a Start). Evidence: `.claude/research/emulator-detach.md`. The helper shows in Activity Monitor as "Pane Emulator", and a TCC prompt the emulator causes (the microphone, with sound on) names it. The takeover wrapper needs no helper: it `exec`s the emulator from the caller's shell, never from Pane.
- **When the emulator ends, Pane's log tells how:** `Stream unexpectedly closed` is a crash (look in `~/Library/Logs/DiagnosticReports/qemu-system-aarch64*.ips`), `Cancelling all calls` is an orderly shutdown that something asked for.

## Updates and releasing (not released yet)

Plan, open questions and the credential steps: `../plans/pane-ship.md`. Mirrors Drop (`../drop/AGENTS.md`, Releasing).

- **Updates:** Sparkle (pinned `exact:`) with Pane's own surfaces, never Sparkle's windows. `Sources/Pane/Updates/UpdateModel.swift` is the state machine (no Sparkle types; `PaneTests/UpdateModelTests` drive it with a fake feed), `UpdateDriver.swift` maps Sparkle's callbacks to it, and `UpdatePopupController` is the `UpdateSurface`: the popup shows an update that is ready or waits for Download, and follows a download started from its own button. Everything else (a check by hand, its result, a download it started) shows in Settings' Version row, which reads the model. "Check for Updates…" in the app menu opens Settings at the Pane group and runs the check. Later keeps the update: it installs when Pane quits, and Settings shows the banner until then.
- **Only Developer ID builds update.** `build-app.sh` writes `SUFeedURL` and `SUPublicEDKey` only for a real `SIGN_IDENTITY` (or when `SPARKLE_PUBLIC_KEY` is passed for a test), and the app starts Sparkle only when both are there. Debug builds never do, except with `-PaneUpdateFeed <url>` (a local test appcast).
- **Releases** are built only by `.github/workflows/release.yml` (tag `vX.Y.Z` or by hand): the CI check (below), `build-app.sh` (env `VERSION`, `BUILD`, `SIGN_IDENTITY`), `scripts/package-dmg.sh <version>` (DMG; signs, notarizes and staples when its env is set), `sign_update`, `scripts/appcast.sh`, then a GitHub release with `Pane-<version>.dmg` (what the feed points at), `Pane.dmg` (the same file under a fixed name, for the website's link `releases/latest/download/Pane.dmg`, as Drop does) and `appcast.xml`. Notes come from the version's section in `RELEASE_NOTES.md`. Nothing is signed or notarized from a laptop.
  - **Tests run once.** Before any secret, `.github/scripts/ci-passed.sh` looks for a passing CI run on the tagged commit, or on the commit under it that differs only in files CI ignores (a release-notes commit on top counts). A CI run still going is waited for, up to 30 minutes. With no pass, the release runs `.github/scripts/test.sh` itself (the same lint, build and tests CI runs).
  - **Cache:** the release restores main's SwiftPM cache read-only (`actions/cache/restore`) and never saves one; a miss is a clean build. Tags can read main's caches but not each other's, so only CI on main feeds it.
  - **Two jobs:** `build` (macOS, read-only token, the `release` environment) hands the DMG, `Pane.dmg`, the appcast and the notes as an artifact to `publish` (Linux), the only job with `contents: write`.
  - **Dry run:** Actions › Release › Run workflow with a version and `dry_run` ticked. Same steps up to the DMG, signed ad hoc and not notarized, appcast with a placeholder signature, nothing uploaded. It takes no environment (so no secrets, no tag-only rule, no reviewer) and its own concurrency group, so it can't cancel a release waiting in line. Safe any time.
- **CI** (`.github/workflows/ci.yml`, main pushes and pull requests, no secrets): lint, build, tests (`.github/scripts/test.sh`), then `build-app.sh` ad hoc and `codesign --verify` on the app and the helper. Docs-only changes (`**.md`, `docs/`, `LICENSE`) skip it; that list is also `IGNORED` in `ci-passed.sh`, so change both together. A newer push to the same branch cancels the run before it. The test step stops after 15 minutes (the release's fallback after 20), so a hang fails fast; the suite once hung on the hosted runners' 3 cores while passing locally. The SwiftPM cache (`.build`: dependencies' checkouts and their debug and release builds) is keyed on the Xcode build, the Swift version and `Package.resolved`; main saves it when the key is new, pull requests only restore it. Pane's own code always recompiles (checkout gives every source a new timestamp), and `build-app.sh` signs a fresh bundle. Every action is pinned to a commit SHA.
- **Secrets** belong to the `release` environment and are set by Jatin only. `scripts/new-update-key.sh` makes the update-signing key; agents never run it.
